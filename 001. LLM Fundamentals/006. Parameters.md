The 'Parameters' are the learned numbers inside an LLM. They are what the model “knows” after training.

In simple terms, parameters are the weights and biases that define the behavior of the model.

An LLM is ultimately a large mathematical function.

Parameters are the numbers that control this function.

When people say:

    7B model
    70B model
    175B model

they mean roughly:

    7 billion learned parameters
    70 billion learned parameters
    175 billion learned parameters

For example, an embedding vector has learned numbers:

    "cat" -> [0.12, -0.44, 0.08, 0.91, ...]

Those numbers are parameters.

During training, the model predicts the next token, checks how wrong it was, and slightly updates its parameters so it gets better next time.

A transformer also has many weight matrices inside:

    attention layers
    feed-forward layers
    normalization layers
    output layers

All of those contain parameters.

In an LLM, parameters decide things like:

    - how token IDs become embeddings
    - what patterns attention heads look for
    - how strongly tokens influence each other
    - what features feed-forward layers detect
    - which next tokens become more likely

So when a model has more parameters, it has more capacity to store and represent patterns. But bigger is not automatically better. Training data quality, architecture, compute, alignment, and inference setup also matter a lot.

Parameters do not store text or facts directly.

Instead, they encode:

    - statistical patterns of language
    - relationships between words and concepts
    - grammar and syntax
    - reasoning tendencies

All of this is stored as 'distributed numerical representations', not explicit knowledge.

Parameters are initialized randomly and then updated during training. This is typical process -

    - Model predicts the next token
    - Compare with the correct token
    - Compute error (loss)
    - Adjust parameters to reduce error

This is done using optimization methods like 'Gradient Descent'.

The number of parameters affects:

    - model capacity (how complex patterns it can learn)
    - performance on tasks
    - memory and compute requirements

So, small models can have millions of parameters while modern LLMs can have billions or more parameters.

Remember that parameters are not a database. They do not store sentences explicitly. More parameters are not always better since quality of data and training matters as well.

Think of parameters as -

    billions of tiny knobs that get adjusted during training to make the model better at predicting language.

# EXAMPLES

Imagine a very simple prediction rule:

    output = input * weight

Here, 'weight' is a parameter.

If the weight is 2, then -

    input 5 -> output 10

If the weight is 3 -

    input 5 -> output 15

The model’s behavior changes because the parameter changed.

Now imagine a model with many such numbers:

    output = input1 * weight1 + input2 * weight2 + input3 * weight3

The weights ar the parameters -

    weight1 = 0.7
    weight2 = -1.2
    weight3 = 3.4

During training, the model adjusts these numbers to make better predictions.

Let's take an example of house price prediction. Let's say we predict the house price by -

    price = size * weight1 + bedrooms * weight2 + location_score * weight3

Initially, the model may guess bad weights -

    weight1 = 1
    weight2 = 1
    weight3 = 1

It makes a prediction, compares with the real price, and updates the weights.

After a lot of training, it may learn -

    weight1 = 250
    weight2 = 10000
    weight3 = 50000

Now the parameters capture useful patterns:

    larger size -> higher price
    better location -> much higher price

So in plain terms:

    Parameters are adjustable knobs.

    Training is the process of turning those knobs until the model’s predictions become better.
