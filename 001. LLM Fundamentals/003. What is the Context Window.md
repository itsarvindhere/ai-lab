The context window is the maximum number of tokens a model can process at once. This directly defines how much information a model can "see" when generating a response.

So, an LLM only knows what is inside its current context window. Anything outside it effectively does not exist.

# WHAT COUNTS TOWARDS THE CONTEXT WINDOW?

You might think that context window is affected by just what we pass to the LLM as prompt. But that is not it.

Everything in a request is part of the context -

    - your current prompt
    - previous conversation messages
    - system instructions
    - retrieved documents (in RAG systems)
    - the model’s generated output

So the limit is shared across input + output.

Let's say a model has a context window of 8,000 tokens.

    Prompt        → 3,000 tokens
    History       → 2,000 tokens
    Response      → 1,000 tokens
    ------------------------------
    Total         → 6,000 tokens ✅

So, it is still within limit.

But -

    Prompt + History → 7,500 tokens
    Max output       → ~500 tokens

In this case, the model cannot generate a long response because the context window is almost full.

Context window matters because the larger the window, the model can remember most past messages. Similarly, a smaller context window means older messages get truncated. This is why long chats sometimes “forget” earlier details.

# WHAT HAPPENS WHEN CONTEXT WINDOW IS EXCEEDED?

There are two common behaviors -

    1. Truncation - Older tokens are removed (usually from the start).

    2. Rejection - The request fails because it exceeds the limit.

It is important to know that context is not the same as memory. Context is a temporary input window whereas the memory is an external system feature if implemented.

The model itself does not persist information beyond the current request.

So, the summary is that the context window is the maximum number of tokens an LLM can consider at once, limiting how much information it can use to generate a response.

# LOST IN THE MIDDLE PROBLEM

This refers to a behavior in LLMs where the model is less likely to use or correctly recall information that appears in the middle of the context, compared to the beginning or the end.

If you place important information in different positions:

    [Beginning]   → High attention  
    [Middle]      → Often ignored or weaker  
    [End]         → High attention  

The model tends to:

    - use early context (prompt framing)
    - use recent context (recency bias)
    - underutilize middle content

This is much more pronounced the larger the context window gets.

Even though modern LLMs support extremely large context windows (hundreds of thousands to millions of tokens), this does not mean they can effectively utilize all of that information.

As the context grows:

    - attention becomes more distributed
    - important signals compete with irrelevant tokens
    - the “lost in the middle” effect becomes more pronounced

This means that simply increasing the amount of input does not guarantee better performance.

However, this does not imply that fewer tokens are always better.

Provide just enough context to solve the task, while avoiding unnecessary or irrelevant information.
