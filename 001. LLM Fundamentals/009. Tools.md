A plain LLM can only generate text from what it already has in context.

But, LLMs can use 'tools' to do things like -

    - search the web
    - read a file
    - run code
    - query a database
    - use a calculator
    - send an email
    - check a calendar
    - create an image
    - call an API

A tool is a function or service an AI system can use to get information or take action.

For example, if we ask an LLM -

    What is 28493 * 7192?

An LLM might try to reason it out and make a mistake. But, with a calculator tool, the system can call -

    calculator.multiply(28493, 7192)

And get the exact result.

Another example can be if we ask an LLM -

    What is the weather in Mumbai today?

The model may not know today's weather from training. So, it can use a 'weather' tool -

    weather.get("Mumbai")

Then, it uses the result to answer.

There is something call a 'System Prompt' that is used to give the LLM the tools. The system prompt describes to the LLM what it is supposed to be doing. We can use it to tell LLM what tools it can use.

So, to LLM, we provide the name of the tool, what it does, and the parameters it takes. For example, a 'writeFile' tool 'writes a file to the file system' and the parameters it takes are 'path' and the 'content'.

These parameters are specified in JSON schema and we can pass anything that JSON schema supports like objects, arrays etc. So, in our case, it might look like -

    {
    "system": "You are a helpful assistant. Use tools when needed.",
        "tools": [
            {
                "name": "get_weather",
                "description": "Get current weather for a city.",
                "input_schema": {
                    "city": "string"
                }
            },
            {
                "name": "calculator",
                "description": "Solve arithmetic expressions.",
                "input_schema": {
                    "expression": "string"
                }
            }
        ],
        "user": "What is the weather in Mumbai and what is 25 * 312?"
    }

The LLM receives something like -

    Available tools:
        - get_weather(city)
        - calculator(expression)

Then, it can decide -

    I need weather data and arithmetic.

So it asks for tool calls:

    {
        "tool_calls": [
            {
                "name": "get_weather",
                "arguments": {
                    "city": "Mumbai"
                }
            },
            {
                "name": "calculator",
                "arguments": {
                    "expression": "25 * 312"
                }
            }
        ]
    }

But there is one important aspect.

The LLM does not directly run tools by itself. The app around the LLM gives it a list of tools, watches for tool-call requests, runs the tool, then sends the result back to the model.

The flow is -

    User
        -> App sends prompt + tool descriptions to LLM
        -> LLM chooses a tool call
        -> App executes the tool
        -> Tool returns result
        -> App sends result back to LLM
        -> LLM produces final answer

You can think of the tool list as part of the LLM’s temporary context for that request.

It is similar to saying -

    For this conversation, you have access to:
    1. calculator
    2. weather API
    3. file reader

But the model does not permanently gain those tools. If the app does not include the tools in the next request/session, the model cannot use them.
