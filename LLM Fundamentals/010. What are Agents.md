A plain LLM works like this -

    User asks -> model answers

An Agent works more like this -

    User gives goal
        -> agent plans
        -> agent chooses actions
        -> agent uses tools
        -> agent observes results
        -> agent adjusts
        -> agent continues until done

So, it is a loop where the agent decides when to stop.

An agent is an LLM-powered system that can reason, take actions, use tools, and continue working toward a goal.

So, if we say -

    Find bugs in this codebase and fix them.

A normal chatbot might say -

    Here are some possible bugs...

An agent might do this -

    1. Inspect the files
    2. Run tests
    3. Read error logs
    4. Edit code
    5. Run tests again
    6. Summarize what changed

That loop is what makes it agentic.

The basic agent loop is -

    Goal
        -> Think / plan
        -> Act
        -> Observe result
        -> Update plan
        -> Act again

This is sometimes called a reason-act-observe loop.

So, when we talk about Agents vs LLMs, it is important to understand that LLMs generate text from input while Agents use an LLM plus tools, memory and control loop to accomplish some tasks.

# KEY PIECES OF AN AGENT

## 1. LLM

The language model is the reasoning and decision-making part. It decides things like -

    - What should I do next?
    - Which tool should I use?
    - Did the result solve the problem?
    - Do I need more information?

## 2. TOOLS

Tools let the agent interact with the world. For example -

    - search the web
    - read files
    - write files
    - run code
    - query a database
    - send an email
    - open a browser
    - call an API

Without tools, the agent can mostly only produce text.

## 3. MEMORY / CONTEXT

Agents need to keep track of what has happened.

This can include -

    - conversation history
    - files read
    - tool outputs
    - previous decisions
    - user preferences
    - task state

Some memory is temporary, inside the context window. Some can be stored externally.

## 4. PLANNING

Agents often break big tasks into smaller steps.

For example -

    Goal: Build a weather app

    Plan:
        1. Inspect project
        2. Find frontend framework
        3. Add weather API client
        4. Build UI
        5. Test locally

## 5. PERMISSIONS / GUARDRAILS

Because agents can take actions, they need limits.

For example -

    - Ask before deleting files
    - Ask before sending emails
    - Ask before spending money
    - Do not expose secrets
    - Do not run unsafe commands

This is important because agents are not just answering; they may be changing things.

# AGENTS vs WORKFLOWS

You might have also heard of 'Workflows'. While Agents decide their own path while working towards a goal, workflows are predefined paths.

A workflow is like -

    Step 1 -> Step 2 -> Step 3 -> Step 4

An agent is more like -

    Goal -> decide next step -> act -> observe -> decide again

A workflow has a mostly fixed sequence of actions.

For example -

    When a support ticket arrives:
        1. Classify ticket
        2. Search knowledge base
        3. Draft reply
        4. Send to human reviewer

The system may use LLM inside some steps, but the overall path is designed in advance. So if you build -

    summarize document -> extract action items -> email summary

This is a workflow. The LLM helps, but it is following a script.

An agent has more freedom to choose what to do next.

For example -

    Goal: Fix the failing tests in this project.

The agent might -

    1. Run tests
    2. Read the failing test
    3. Inspect source code
    4. Make a code change
    5. Run tests again
    6. Notice a new failure
    7. Read another file
    8. Adjust the fix
    9. Stop when tests pass

The exact path is not fully known in advance. The agent adapts based on what it observes.

So to summarize -

    Workflow:
    "If X happens, do Y, then Z."

    Agent:
    "Given this goal, figure out what to do next."
