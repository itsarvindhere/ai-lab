Inference is what happens after training, when you actually use the LLM.

Training is -

    learn parameters from data

Inference is -

    use the learned parameters to generate an answer

So, if we ask an LLM to -

    Explain gravity simply.

The model is no longer learning from that message. It is now using the parameters that it already learned during training to predict what text should come next.

This is the basic inference loop -

    1. User prompt is tokenized
    2. Token IDs become embeddings
    3. Model processes the context
    4. Model outputs probabilities for the next token
    5. One token is selected
    6. That token is added to the context
    7. Repeat until the answer is complete
    
So, let's say the prompt is -

    The capital of France is

The model may output probabilities like -

    Paris     0.86
    London    0.03
    Berlin    0.02
    Rome      0.01

During inference, the system chooses one token from that probability distribution. If it chooses Paris, the text becomes:

    The capital of France is Paris

Now, the model predicts the next token again -

    "."       0.60
    ","       0.20
    " and"    0.05

This continues token by token.

So, while in training the parameters are updated, they remain fixed in inference.

During inference, the model does not permanently learn from your prompt. Your prompt affects the current answer because it is in the context window, but it does not rewrite the model’s parameters.

There are several settings that can affect how the model chooses tokens.

## 1. TEMPERATURE

Temperature is a parameter for adjusting the output of LLMs.

Basically, low temperature means safer, more predictable answers. High temperature means more varied and creative answers.

## 2. TOP-K / TOP-P SAMPLING

This limits which tokens the model can choose from. So, instead of choosing every possible token, it samples from the most likely group.

Top-K limits choices to the K most likely tokens.

Top-P selects from the smallest set of top tokens whose cumulative probability exceeds P.


## 3. MAX LENGTH

You can manage the number of tokens the model generates by adjusting the max length. Specifying a max length helps you prevent long or irrelevant responses and control costs.

## 4. STOP SEQUENCES

A stop sequence in an LLM is a user-defined string (characters or tokens) that tells the model to immediately halt text generation when it appears in the output. It acts as an external control mechanism to guarantee concise, structured responses and prevent the model from generating unwanted, long-winded text or continuing a conversation too long

For example, you can tell the model to generate lists that have no more than 10 items by adding "11" as a stop sequence.
